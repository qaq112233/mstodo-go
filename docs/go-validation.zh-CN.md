## 本次真实微软读写验证

在提交首版代码 `bb0ec0d` 后，按用户要求启动本机 Go 服务，使用独立私有 SQLite 数据目录。复用原项目已有的微软应用信息，经设置网页和已经登录的浏览器**重新完成 Go 授权**；没有导入旧服务 refresh token，也没有修改微软应用登记、旧部署或旧任务。

### 初始化修复

真实浏览器首次提交设置时遇到 `403 csrf_rejected`。原因是页面按设计发送 `Referrer-Policy: no-referrer`，原生 POST 根据 [Fetch Standard 的 Origin 规则](https://fetch.spec.whatwg.org/#origin-header) 会发送 `Origin: null`。实现现仅在同时收到浏览器 `Sec-Fetch-Site: same-origin` 时认可该来源；独立 CSRF 校验仍保留。补上回归测试后，浏览器原生表单保存返回 303，微软授权和账号校验成功。

浏览器输出和临时数据均排除在 Git 之外；应用信息中转文件已删除。仓库只记录脱敏结论，不保存真实账号地址、任务 ID、标题、浏览器 token、授权码或 Cookie。

### 只读比对

- Go `GET /api/v1/lists`：HTTP 200，原清单目录 13 个。
- Go `GET /api/v1/myday`：HTTP 200，显式本地日期 `2026-10-24`，11 个任务，其中 1 个已完成。
- 通过浏览器自己的授权独立调用同日期 feed：HTTP 200，1 页完整返回，11 个任务、1 个已完成。与 Go 的**任务 ID 集合、状态及排序全部一致**。

### 隔离写入与网页确认

新建两个带本次随机标记的专用测试清单，创建两个测试任务、两个步骤和一个关联链接。测试脚本维护本次创建 ID 的白名单，所有修改、移动和删除都必须落在这两个清单内，且不得属于测试前的原 13 个清单；原有任务只读取。

真实通过项目：

- 清单创建、读取、改名；任务创建、正文、重要性、日期、未来提醒字段的保存和回读。
- 重复规则保存及回读；重复、提醒、起止日期显式 null 清空；提醒已关闭，没有等待实际通知或重复实例推进。categories 本次仅验证空数组，未验证非空分类标签。
- 步骤创建、勾选、inline 顺序读取和排序；关联链接创建、读取与修改。
- 清单任务手动顺序；指定两个测试清单的 delta 基线和中文包含搜索返回 2 个测试任务。
- 在微软网页重新加载后能看到两个测试清单和测试任务，清单内 B 在 A 前的顺序与 Go 回读一致。
- 两个测试任务加入 My Day 后，完整 feed 为 13 项；My Day 排序写入及完整 feed 回读通过。
- 测试任务完成后仍在 My Day 中，`includeCompleted=false` 正确排除它；随后恢复为 notStarted。两个测试任务移出 My Day 后恢复原成员集合。
- 原任务 re-parent 到另一个测试清单，返回不同的新任务 ID；新 ID 可由 Graph 读取，两个步骤及其勾选状态、一个关联链接仍保留。没有附件样本，不能据此宣称附件内容已验证。
- 移动后的步骤/链接删除、任务删除及清单删除通过。

步骤和 My Day 排序本次通过写入及上游重读验证，没有在网页逐项拖动核对；网页人工顺序观察仅覆盖清单任务。

### 清理与授权持久化

- 测试清单、任务和子资源均已清理，微软网页不再显示本次测试标记。
- 清理后 Graph 清单 ID 集合仍为原 13 个，My Day 恢复原 11 个；按 ID 比较的**完整 My Day 返回字段**与测试前相同，包括完成状态、排序及最后修改时间。
- 官方 Go SDK 通过 Bearer MCP 连接读取真实 My Day，11 项的完整任务字段和顺序与 REST 相同，REST 快照命中缓存。真实业务写入在本次通过 REST 执行；最终 MCP 产品客户端尚未验收。
- 仅重启本次 Go 测试进程后，授权仍有效；强制重新读取 My Day HTTP 200，11 项完整字段仍与测试前一致。

这些是本机地址上的真实微软访问，不等同于生产 HTTPS、容器或墨水屏验收。180 秒过期边界、跨天、限流故障和并发刷新仍主要由自动化测试验证，本次没有人为等待或触发这些条件。
